# 💳 Credit Card Fraud Detection on Imbalanced Data

Detecting fraudulent card transactions when only **~0.17 %** of them are fraud. Compares **Logistic Regression** and **XGBoost**, each with three imbalance strategies (none, **class weights**, **SMOTE**), evaluated with **precision, recall, F1 and PR-AUC** (not accuracy), with a confusion matrix, threshold tuning and **SHAP** explainability.

## Dataset
**Credit Card Fraud Detection** (ULB Machine Learning Group, Kaggle): 284,807 transactions by European cardholders over two days, 492 frauds (0.172 %). Features `V1–V28` are PCA components (anonymised), plus `Time`, `Amount` and the label `Class` (1 = fraud).
<https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud>

**Option B: manual**: download from the page, unzip, place `creditcard.csv` in `data/`.

## Workflow
```
creditcard.csv
   │ drop exact duplicates
   ▼
stratified split 70 / 15 / 15  (train / validation / test)
   │ fit StandardScaler on TRAIN only (Time, Amount)
   ├────────────── train ──► [SMOTE on train only] ──► 6 models
   │                                                     LR × {none, class_weight, SMOTE}
   │                                                     XGB × {none, scale_pos_weight, SMOTE}
   ├── validation ──► choose decision threshold (max F1) + choose best model (PR-AUC)
   └── test ────────► final, untouched report: precision, recall, F1, PR-AUC, confusion matrix
                      └─► SHAP on the best XGBoost model
```
Key design decisions: (1) duplicates removed to avoid leakage, (2) scaler and SMOTE fitted on training data only, (3) the threshold and the "best" model are picked on the validation set so the test set is an honest final exam.

## Concepts explained
**Class imbalance**: one class is far rarer than the other (here ~1 fraud per 580 legit). A model can reach 99.8 % accuracy by always predicting "legit" while catching zero fraud. This is the *accuracy paradox*, and the reason we use other metrics.

**Class weights**: make mistakes on the rare class cost more in the loss. Logistic regression: `class_weight="balanced"` weights each class inversely to its frequency. XGBoost: `scale_pos_weight = n_legit / n_fraud`. No data is changed, only the penalty.

**SMOTE (Synthetic Minority Over-sampling Technique)**: creates new *synthetic* fraud rows by picking a fraud, picking one of its k nearest fraud neighbours and generating a point on the line between them. It is better than duplicating rows because it adds variety. Rules: apply it **only to the training set** (never validation/test, or you evaluate on fake data and leak information), and after the split. Here `sampling_strategy=0.1` raises frauds to 10 % of legit rows; full 1:1 balance often adds noise.

**Precision** = TP/(TP+FP): of the transactions we flagged, the share that were truly fraud (low → annoyed customers, wasted reviews). **Recall** = TP/(TP+FN): of all frauds, the share we caught (low → money lost). **F1** = harmonic mean of the two; it is low if either is low.

**Confusion matrix**: counts of TN, FP, FN, TP. FN = missed fraud, FP = false alarm.

**ROC-AUC vs PR-AUC**: ROC-AUC uses the false-positive *rate*, which is divided by the huge legit count, so it looks great even for weak models. PR-AUC (average precision) focuses on the rare class only; a random model scores about the fraud rate (~0.0017), so it is far more informative here.

**Decision threshold**: models output probabilities; 0.5 is just a default. Moving the threshold trades precision for recall. We pick the F1-maximising threshold on the validation set (`threshold_curve.png`). In real life you would choose it from the business cost of a missed fraud vs a false alarm.

**XGBoost**: gradient-boosted decision trees; trees are built one after another and each new tree corrects the errors of the previous ones. It captures non-linear patterns and feature interactions, handles different scales, and is usually strong on tabular data. Logistic regression is the simple, interpretable linear baseline.

**SHAP**: based on Shapley values from game theory; assigns each feature a contribution to each individual prediction (positive pushes toward fraud). `TreeExplainer` computes them exactly for tree models. The beeswarm plot shows global importance and direction; the waterfall plot explains a single transaction, useful for regulators and fraud analysts.

## Limitations & future work
- Features are PCA-anonymised, so SHAP explains `V14`-style names rather than business concepts
- A single random split; use stratified k-fold or a time-based split (train on earlier days, test on later) for a more realistic estimate
- Next: hyper-parameter tuning (Optuna), probability calibration, cost-sensitive threshold using real € costs, concept-drift monitoring
